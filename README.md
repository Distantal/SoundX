# SoundX

本地数字音频工作站(DAW)。作者 **Distantal**,开源免费:源码随程序提供,可自由编译、修改和分发。当前版本 **0.07 Beta**。

技术栈:C++20 + JUCE 8(音频引擎、VST2 / VST3 宿主、界面全部自绘),MSVC 构建。单窗口:控制栏、检查器、编排区、底部调音台 / 钢琴卷帘,扁平配色。

## 运行

`dist\SoundX.exe` 是独立程序,双击即可运行。也可以用 `build.ps1 -Run` 编译并启动。

程序动态链接 Microsoft C++ 运行库(`MSVCP140.dll` / `VCRUNTIME140.dll` / `VCRUNTIME140_1.dll` / `MSVCP140_ATOMIC_WAIT.dll`)。安装程序把这几个 DLL 和 `SoundX.exe` 一起写到安装目录(**app-local 部署**),所以没装过“Microsoft Visual C++ 2015-2022 Redistributable”的干净系统也能直接启动;这几个 DLL 的来源是 `build.ps1` 从 VS 的 `VC\Redist` 复制到 `dist\runtime\`(当前 14.44.35211,x64),再由安装程序内嵌。手动复制 `dist\SoundX.exe` 到别的机器时,请把 `dist\runtime\` 里的 DLL 一起拷过去。

`SoundX.exe` 静态导入了这 4 个运行库 DLL,以及 `KERNEL32` / `USER32` / `GDI32` / `SHELL32` / `ole32` / `OLEAUT32` / `COMDLG32` / `ADVAPI32` / `SHLWAPI` / `WINMM` / `IMM32` / `COMCTL32` / `dwmapi` / `d2d1` / `dxgi` / `d3d11` / `dcomp` 这些系统 DLL 和 UCRT(`api-ms-win-crt-*`,Win10 起随系统提供)。所以运行要求是 **Windows 10 / Windows 11 64 位**(`dcomp.dll` 和 UCRT 是系统组件,Win8.1 以下不再支持),不需要管理员权限、不需要预装任何运行库。

`dist\SoundX-0.07Beta-Setup.exe` 是安装程序(可改安装位置、可选桌面 / 开始菜单快捷方式、默认安装后启动,附带 `Uninstall SoundX.cmd`)。安装到目录里的东西:`SoundX.exe`、Microsoft C++ 运行库的 4 个 DLL(app-local,不需要另装运行库)、`SoundX-Manual.pdf`(使用说明书)和卸载脚本。静默安装:`SoundX-0.07Beta-Setup.exe --silent <目录> [--zh]`。重新打包用 `package.ps1`,安装包文件名会自动带上 `CMakeLists.txt` 里的版本号(`SOUNDX_VERSION_LABEL`);打包结束时会自动做一次静默安装,校验装出来的 `SoundX.exe` 与刚编译的完全一致(防止安装包里嵌了旧程序)。exe 与安装包的版本资源里都是 `0.7.0`,`CompanyName` / 作者是 `Distantal`。

首次启动会弹出"插件管理器",点 `扫描 / 选项` 扫描已安装的 VST2 / VST3。VST2 默认会扫描 `C:\Program Files\Common Files\VST2`、`VSTPlugins` 以及 `VST_PATH`,VST3 扫描 `Common Files\VST3`。也可以把插件文件夹(或插件文件)直接拖进扫描窗口,拖进来的文件夹会加入扫描路径,下次 `扫描全部插件文件夹` 会一起扫。

**启动时是一个空工程**:没有轨道、没有乐器,界面里只显示空的编排区(提示"还没有轨道。点击 + 按钮或使用轨道菜单添加")。添加**软件乐器轨道**时也不会自动挂任何乐器(包括内置的 `SX Synth` / `SX Sampler`),轨道是"干的",点乐器槽自己选 VST / VST3 / 内置合成器 / 内置采样器。如果每次都想从自己的一套轨道开始,就摆好之后用 `文件 > 保存为工程模板...` 存一份模板(存在 `%APPDATA%\SoundX\project-template.sxp`),下次启动直接加载它;`文件 > 从模板新建工程` 可以随时再开一份,`文件 > 删除工程模板` 恢复成空工程启动。模板里连乐器、效果器、路由、速度和轨道名都会带上(插件的音色状态也保存)。

## macOS

macOS 版从同一份源码构建(VST2 关闭,ASIO 关闭),打包脚本是 `package-mac.sh`:

```bash
./package-mac.sh                              # 通用二进制(arm64 + x86_64),ad-hoc 签名,不启用 hardened runtime
CODESIGN_ID="Developer ID Application: ..." ./package-mac.sh   # 正式签名 + hardened runtime + entitlements(再拿去公证)
SOUNDX_MAC_ARCHS=arm64 ./package-mac.sh       # 只编本机架构(体积小,但只能加载同架构的插件)
```

三点和 Windows 不一样,移植时最容易踩:

1. **架构必须和插件一致**。一个 VST3 bundle 里要么是通用二进制,要么只有一种架构,`dyld` 不能混;所以 `package-mac.sh` 默认编**通用二进制**。装了 x86_64-only 的插件而 SoundX 只有 arm64(或反过来),插件会报 `Unable to load VST-3 plug-in file`,扫描也只会得到 0 个类型。
2. **hardened runtime 必须带 entitlements**。`codesign --options runtime` 会打开 macOS 的 library validation:它只允许加载"苹果签名的"或"和主程序同一 Team ID 的"二进制,第三方插件全都会被拒。插件宿主必须带 `com.apple.security.cs.disable-library-validation`(以及录音要用的 `com.apple.security.device.audio-input`),文件在 `installer/SoundX.entitlements`,`package-mac.sh` 签名时会自动带上;本地 ad-hoc 构建默认**不**开 hardened runtime,插件才能直接加载。用 Xcode 构建时 CMake 会把同一个 entitlements 交给 Xcode(`-DSOUNDX_MAC_HARDENED=ON` 再打开 hardened runtime)。
3. **界面字体用系统字体**。之前窗口/菜单里写死了 Windows 的 `Segoe UI`,macOS 上没有这个字体,JUCE 会退回另一个字形,中文还要再换一次字体,于是菜单看起来"字体不适配"。现在整个界面(包括 JUCE 自己画的对话框、菜单、输入框)都用系统字体(`system-ui`:macOS 上是 SF + 系统中文回退,Windows 上是 Segoe UI),粗体也按系统字体的对应字面取。

插件的默认扫描路径和 Windows 不同(VST3):`/Library/Audio/Plug-Ins/VST3`、`~/Library/Audio/Plug-Ins/VST3`;日志在 `~/Library/Application Support/SoundX/plugin-scan.log`,设置与插件列表也在同一目录。插件加载失败时,macOS 版会把 `dyld` 的原话一起写进错误和日志(架构不符 / 代码签名损坏 / 被 library validation 拒绝,这三种会给出完全不同的文字),日志开头还有一行 `---- scan started: macOS 15.3 / arm64 ----` 说明这次扫描是什么系统、什么架构:

```bash
# 单个插件诊断:结果写到 /tmp/sx/selftest.log
/Applications/SoundX.app/Contents/MacOS/SoundX --selftest /tmp/sx --scan "/Library/Audio/Plug-Ins/VST3/Serum2.vst3"
# 只扫一个目录并打开插件管理器
/Applications/SoundX.app/Contents/MacOS/SoundX --plugin-manager --scan-folder "/Library/Audio/Plug-Ins/VST3"
```

扫描仍然是独立进程(`SoundX --plugin-scan-worker`)。macOS 上不允许跨线程操作窗口,所以"扫描中自动关掉插件弹窗"只在 Windows 上做;macOS 上插件自己弹出的窗口会挡住扫描,由 30 秒空闲超时结束该辅助进程并把插件标红。录音需要麦克风权限(CMake 已经写好 `NSMicrophoneUsageDescription`)。

扫描过程**不会卡住界面**:查找插件文件(递归遍历插件目录)和加载每个插件都在扫描线程里进行,窗口只是每 100 ms 读一次进度并重绘。所以扫描时列表照常滚动、按钮照常响应,标题栏不会出现 `(未响应)`;进度条上方显示 `正在扫描 12/240 插件文件名`,旁边两个按钮:**`跳过此插件`** 只放弃当前正在加载的那一个插件(结束它的辅助进程)并接着扫后面的文件,状态条上会多出 `已跳过：N`,`停止` 则是结束整次扫描(同样结束当前插件的辅助进程)。两者都不会把插件当成坏插件:跳过的插件既不会进列表,也不会被标红(下次扫描还会再试,不是永久忽略),只在扫描日志里留一行 `skipped by the user: <路径>`,扫描结束后 `扫描 / 选项 > 扫描报告` 会列出这次被跳过的文件名。一个插件要加载好几分钟、或者你根本不想扫它时用 `跳过此插件`,不必为了它放弃整次扫描(遍历插件文件夹的那一步没法中途跳过,`停止` 要等遍历结束,通常 1 秒以内)。

扫描本身在**独立进程**里进行:每个插件文件由一个 `SoundX.exe --plugin-scan-worker` 辅助进程加载,主程序只收描述信息。文件夹扫描会同时启动最多 **4 个辅助进程**(`SOUNDX_SCAN_WORKERS` 可覆盖),并且已经扫描过、文件修改时间没变的插件**不再启动辅助进程**,直接复用 `plugins.xml` 里的结果;所以整库重扫通常只是一次快速目录遍历。插件扫描时崩溃、卡死或弹窗都只影响辅助进程(弹窗会被隐藏并关闭;辅助进程 30 秒没有任何进展就会被结束,最多 5 分钟),主程序不会闪退、也不会被插件卡住;出问题的插件在列表里标红(说明列写着原因),`扫描 / 选项 > 扫描报告` 列出全部失败项,完整记录在 `%APPDATA%\SoundX\plugin-scan.log`(每次扫描结束会记一行耗时与文件数)。重新启用:右键该行 `重新启用(并重新扫描)`。单个插件的诊断可以直接跑:`SoundX.exe --selftest <目录> --scan "<插件路径>"`。

语言默认跟随系统(中文 / 英文),可在 `视图 > 语言` 中切换,重启生效。中文翻译覆盖菜单栏、右键菜单、下拉框、对话框、提示气泡和状态文字(`视图 > 语言` 里选 `自动` 就是跟随系统);品牌名、单位(WAV / dB / BPM / kHz)、快捷键名和插件自己提供的名字(插件名、参数名、预设名)保持原文,这些是数据不是界面文字。自检会遍历整个菜单栏(含所有子菜单,120 多项)并检查有没有漏翻的条目,一个都不许剩 —— 以后加菜单忘了写翻译会直接报错。

## 使用说明书

`docs/SoundXManual.pdf` 是随程序发布的中文说明书(作者 Distantal,9 页):简介、安装与首次启动、界面、轨道与片段、钢琴窗、混音、录音、MIDI 学习、素材池 / 工程信息 / 导出、快捷键、常见问题、开源与技术说明。

- 这份 PDF 会被**编进 exe**(`juce_add_binary_data`),所以 `帮助 > 使用说明书 (PDF)` 在只拷贝一个 `SoundX.exe` 的机器上也能打开:程序先把它写到 `%APPDATA%\SoundX\SoundX-Manual.pdf`(内容没变就不重写),再交给系统默认的 PDF 阅读器。
- 也可以用命令行直接打开:`SoundX.exe --manual`。
- 改说明书:重新生成 `docs/SoundXManual.pdf` 后重新编译即可,exe 会自动带上新版本(自检里有一条检查它确实在二进制里、并且写出来是 `%PDF-` 开头)。

## 功能

| 需求 | 实现 |
|---|---|
| 导入 / 导出 MIDI | `文件 > 导入 MIDI`(也可拖入文件;多轨 / 多通道自动拆成轨道,保留 CC、弯音、触后)。导入时会弹出选项:**列出 MIDI 文件里的曲速 / 拍号变化链**(如 `120 → 90 → 150 BPM`、`4/4 → 3/4`)和**工程当前值**,用勾选框决定是否把文件的速度映射写进工程:勾上则工程改用文件的曲速 / 拍号(音符落在同样的拍上),不勾则只导入音符、控制器和轨道名,工程速度不变。这个选择会被记住,拖入文件时直接沿用(工程为空时默认同步,工程已有内容时默认不同步)。`导出 MIDI` 写出 Type 1 标准文件(960 PPQ),**把工程里的每一处曲速 / 拍号变化都写成 conductor 事件**(包括放在最后一个音符之后的变化);线性渐变的曲速按拍写成逐拍速度事件,每拍时长与工程里的曲线完全一致。 |
| CC 编辑 | 钢琴卷帘下方的编辑通道:力度,或任意 CC 0-127、弯音、通道触后。**指针工具**(选择)只选择不写入:点击锚点选中(Shift 加选,再点取消),在通道里拖出**选框批量选中**,`Delete` 删除所选,右键点 / 拖删除锚点。**铅笔工具**负责绘制:单击加点、拖动徒手画曲线、`Shift + 拖动` 画斜线,右键同样删除。**量化开启时**新加和拖动的锚点都吸附到网格(与音符同一档 `1/16`、`1/8` 等,`Alt + 拖动` 临时不吸附);**量化关闭(`Off`)时**不吸附,按像素密度生成密集锚点,画出更平滑的自由曲线。力度通道同理:指针只选音符 / 拖它自己的力度,批量画力度用铅笔。**弯音通道是"弹簧"式的**:它停在正中间(8192),没有锚点的地方画成一条中线的水平线、填色也只填曲线与中线之间的部分,所以**在片段中段画一个弯音不会把后面没编辑的部分一起拽偏** —— 曲线在最后一个锚点后面立刻回到中线,而且**每次画完(松开鼠标)最后一个锚点都自动落在中线上**(单击只放一个点、不改数值);播放与导出 MIDI 走同一套规则(`appendControllerMessages` 在弯音的第一个锚点之前、最后一个锚点之后补上 8192 的回中事件),听到的和看到的一致。其他 CC 保持 MIDI 的"沿用上一个值"行为。 |
| CC 曲线工具 | 工具栏 `力度 v` 右边的下拉(`自由` / `直线` / `正弦` / `三角` / `锯齿`)决定铅笔在控制器通道里画什么:**自由**是手绘;**直线**是按下点到松开点的斜线;**正弦**、**三角**在拖出的时间范围内画满一个波形(两端落在按下时的值、中间到达松开时的值,正弦是平滑的、三角是直边);**锯齿**按拍重复(每拍一段斜坡,到位后跳回)。拖动过程中形状会实时重建,拖过的范围里的旧锚点被替换;`Shift + 拖动` 始终画斜线。**通道的小节线与上方钢琴卷帘完全对齐**:打开左侧"可编辑轨道"列表时,通道和网格一起右移同样的宽度,竖线 / 小节线 / 播放头一条不差。 |
| 反转选中音符 | 选中一段音符后,`编辑 > 反转选中音符`:以选中范围的首尾为轴,把整段乐句在时间上镜像,音高、力度和各自长度保持不变。一次操作一步撤销。 |
| 滑音音符(FL 风格) | 钢琴卷帘工具栏的 **SLIDE** 开关打开后,新画的音符带滑音标记(音符右侧的小斜线),也可先选中已有音符再点 SLIDE 套用。播放时滑音音符从**前一个音符的音高**开始,在音符长度内弯音到写下的音高;内置 SX Synth 通过 RPN 弯音范围支持最多 24 半音,第三方插件也会收到同样的弯音事件(实际范围取决于插件)。 |
| 力度人性化 | 选中音符后按 `H`(或 `编辑 > 力度人性化`),每个音符的力度在 **± 范围**内各自随机浮动:用同一个力度画出来的踩镲、钢琴柱式和弦不再像机器。`Shift+H`(或 `编辑 > 力度人性化(设置)...`、钢琴卷帘工具栏上量化右边的骰子按钮)打开对话框,调**力度幅度**、**时间偏移**(± tick,每拍 960 tick;把音符推离网格,柱式和弦听起来像扫弦)和**分布**(`钟形`:多数音符接近原值、少数偏离较远;`均匀`:整段范围等概率,即 Cubase 的随机化)。对话框里的 `随机化` 每点一次就重新随机一次,**每次都从打开对话框时的力度重新画,不会越点越偏**;整段操作只占**一步撤销**(`Ctrl+Z` 回到打开对话框之前)。幅度会被记住,按 `H` 直接用上次的设置。没有选中音符时作用于整个片段(与量化一致),力度始终夹在 1-127,时间偏移不会把音符推到 0 之前。 |
| 自动化编辑(轨道内) | 轨道头的自动化按钮选择参数后,曲线**直接画在这条轨道的同一行里**(不再占子行),音频块 / MIDI 块自动变淡以便看清曲线,和 Studio One 的 Automation in Track 一样。菜单里的 `在轨道内编辑自动化` 进入编辑模式:整条轨道都能点击加点、拖动改值、右键删点,片段进一步变淡;退出后片段恢复可选。参数可选音量、声像,或任意插件参数(含"最近触碰"的参数)。模式:关闭 / 读取 / 触碰写入(播放时拖动推子或插件旋钮即录入)。Master 行保留独立的自动化子行。 |
| 自动化轨(单独成轨) | 点编排区左上角的 **`+`** 按钮选 `新建自动化轨道...`,先**选择这条自动化要作用于哪一轨**(可以直接选 Master),再选参数,就会在目标轨下面生成一条独立的自动化轨:轨道头显示参数名与所属通道,曲线画满整条轨道,和普通轨一样拖动、加删节点、随工程保存,行高也跟随 Ctrl + 滚轮的轨道高度。右键该轨 `自动化目标轨道` 可以随时改到另一条通道,`移回轨道内部` 则把曲线折回该轨道的同一行;同一个参数只保留一条曲线(移动而不是复制)。 |
| 自动化录制写入 | 把轨道的自动化模式设为 **触碰写入**,播放时以下操作都会写进当前自动化曲线:**拖动推子 / 声像 / 插件旋钮**,**鼠标滚轮**调推子 / 声像 / 旋钮,以及**外部 MIDI 控制器**经 MIDI 学习映射到音量、声像或插件参数后的移动。鼠标滚轮和外部控制器没有"松开"动作,引擎会在停止操作约 350 ms 后自动提交一次写入;每次写入仍是一步撤销。 |
| 轨文件夹(打包 / 子集) | 选中多条轨道后,`轨道 > 将选中轨道打包为文件夹`(或轨道右键菜单):生成一条文件夹轨(一条 Bus),选中的轨道整体移到它下面、**每级缩进 18 px** 并用树线标出归属,同时自动路由到文件夹总线;点文件夹头左侧的三角(或右键 `收起 / 展开文件夹`)把整个子集折叠成一行,子轨仍然发声。子集里再打包会形成二级缩进。`解散文件夹` 把子轨提升一级并保留原来的输出路由,不会静音。文件夹随工程保存、可撤销;拖动文件夹时其子轨一起移动。 |
| 自动化曲线单调 | 节点按拍排序、同一拍上只保留一个节点;相邻节点之间是直线段,曲线只会单调上升或下降,**不会过冲、不会在时间上折返**;拖动节点时被夹在左右邻居之间。绘制与引擎取值走同一个函数,所以看到的曲线就是听到的曲线;速度轨道、片段增益包络与总线自动化同样如此。 |

另有:内置合成器 `SX Synth` 和内置采样器 `SX Sampler`(都在乐器选择列表里,一个插件都不装也能出声;不会自动挂到新轨道上),撤销 / 重做(一次导入 = 一步撤销)、循环播放、片段拆分 / 复制 / 粘贴、电脑键盘演奏、工程保存为 `.sxp`、工程模板(启动工程)。

插件参数手势(第三方插件编辑器里的旋钮拖动)会合并为一次撤销步骤:同一个参数在很短时间内连续收到手势开始 / 结束时不再每次都把整个工程序列化成 XML,而是共用一个检查点;快照重建也做了同样的合并(最短 60 ms 才真正重建一次)。这修的是“挂载某些插件播放一会儿之后,菜单和按钮越来越迟钝”的问题——有些插件会在播放时以几十次每秒的频率上报参数手势或延迟变化,消息线程被反复的“全工程序列化 + 快照重建”占满,单核 / 多核都会卡。另外,界面线程(消息线程)在启动时被提到 **高于普通** 的优先级(仍然低于音频线程),这样 Ozone 这类吃 CPU 的插件在音频线程 / 它自己的线程上满载时,也不会把菜单和按钮饿死;原生插件编辑器窗口的尺寸轮询也从每秒 10 次降到稳定后每秒 1 次。若仍想定位界面卡顿,可以用环境变量 `SOUNDX_UI_PROFILE=<日志文件>` 启动,程序会每 5 秒记录一次消息线程的定时器延迟(avg / max / 超过 150 ms 的次数);`SOUNDX_UI_PRIORITY=highest|above|normal` 可以不改程序就 A/B 界面线程优先级(默认 above;highest 和音频线程同级,可能影响音频余量)。

## 构建

需要 VS 2022 Build Tools(C++ 工作负载与 Windows SDK)。`build.ps1` 会自动载入 MSVC 环境,并使用 VS 自带的 CMake 与 Ninja:

```powershell
git clone --depth 1 --branch 8.0.4 https://github.com/juce-framework/JUCE.git third_party/JUCE
.\build.ps1 -Configure      # 首次配置并编译
.\build.ps1                 # 之后增量编译
```

`third_party/vst2` 中是按公开的 VST 2.4 二进制接口自行编写的最小头文件(`aeffect.h` / `aeffectx.h`),没有使用 Steinberg 的 VST2 SDK。关闭 VST2 宿主:`cmake -DSOUNDX_VST2=OFF`。

ASIO 支持默认开启(`SOUNDX_ASIO`,默认 ON):把 Steinberg ASIO SDK(2.3.3 或更新版本,现以 GPLv3 开源发布)解压到 `third_party/asiosdk`,CMake 会自动把它接入(`JUCE_ASIO=1`)。目录不存在时自动退回 WASAPI / DirectSound;也可用 `cmake -DSOUNDX_ASIO=OFF` 显式关闭。

ARA 支持(`SOUNDX_ARA`,默认 ON):ARA SDK 2.2.0 已放在 `third_party/ARA_SDK`(`ARA_API` + `ARA_Library`,Apache-2.0)。CMake 找到它就调用 `juce_set_ara_sdk_path()` 并定义 `JUCE_PLUGINHOST_ARA=1`,把 JUCE 的 ARA 宿主框架整编进来;SDK 目录不在时自动退回没有 ARA 的构建,`cmake -DSOUNDX_ARA=OFF` 可显式关闭。配置时会打印 `SoundX: ARA 2.2.0 host support enabled`。

## ARA 与 AAX

**ARA**(Audio Random Access,Celemony 的扩展,运行在 VST3 / AU 之上)当前做到哪一步:

- 已经:**SDK 内置 + 宿主框架编进程序**(`ARA 2.2.0`,自检里会打印这一行),插件扫描会把声明了 ARA 的插件标出来——插件管理器的描述列和底部汇总(`ARA: N`)、插入插件的搜索列表右侧都带 `ARA` 标记。
- 已经:**ARA 宿主核心**(`src/engine/AraHost.h`):为一个音频轨建立 ARA 文档——每个音频片段一个 `AudioSource`(直接读片段采样)、一个按时间轴位置摆放的 `PlaybackRegion`,一个 `RegionSequence` + `MusicalContext`,并把插件实例按 playback / editor 角色绑定上去;宿主侧的 `AudioAccessController` 负责把采样喂给插件,`ArchivingController` 暂存插件存档。自检里用 JUCE 的 ARA demo 插件(本地编出的 ARA VST3 夹具)跑通了整条链路:`1 source(s), 1 region(s), playback renderer`。
- 已经:**引擎接入**——把声明 ARA 的插件插到**音频轨**上时,引擎自动为这条轨建立并同步 ARA 文档(音频源 + 播放区域),绑定后按 ARA 规则重新 `prepareToPlay`;这条轨渲染时**不再播原始片段**(否则会和插件的渲染结果叠成双份),关掉/移除插件后恢复。
- 还没做:走带位置按 ARA 规则喂给插件、导出时也走 ARA 渲染,以及把 ARA 存档写进 `.sxp` 并在载入/撤销时恢复。所以现在插件的 ARA 能力已经"能被宿主持有并拿到音频",但**存档还不保存修音结果**。

**AAX**(Avid)不是"还没写",而是第三方宿主**没有可行路径**:

1. 公开的 AAX SDK 只包含**做 AAX 插件**需要的东西;宿主端那一套(`AAX_IController` 背后的服务、页面表、内存与传输同步)是 Pro Tools 自己的实现,不对外授权。
2. AAX 插件按 Avid 的授权只允许在 Avid 认可的宿主里运行,目前唯一在售的 AAX 宿主是 Pro Tools;市面上没有任何第三方 AAX 宿主。
3. JUCE 只带 AAX **插件客户端** SDK(`modules/juce_audio_plugin_client/AAX`),没有 `AAXPluginFormat`——和 VST3 / AU / ARA 不同,AAX 在 JUCE 里根本没有宿主实现。

所以需要和 Pro Tools 交换工程时,现实做法是导出 / 导入 AAF 或多轨 WAV,而不是去宿主 AAX 插件。

**本轮新增的回归测试**:

- **标准化 / MP3 导出的"整段正确"**:把标准化 16 bit 文件和同一段的未标准化 24 bit 渲染逐样本对比(超过一个块的整段,不只看开头),断言缩放后的最大误差 < 0.02 —— 这是"导出第二块以后写坏堆内存"的回归测试(内存池按块扩容的边界),以前会在导出后随机崩溃。

- **插件面板**:`show()` 返回时面板外壳已经出现、编辑器还没构建(说明构建被推迟);构建完成后是真正的 `AudioProcessorEditor`;关闭后窗口仍被缓存(`isOpen=false` 但组件还在),再次打开复用同一个编辑器指针(不重建 UI)。

## 已知限制

- 音频驱动支持 ASIO(需放置 `third_party/asiosdk`,见"构建"一节)、WASAPI(共享 / 独占)与 DirectSound。
- **AAX 插件不能宿主**:AAX 的宿主端 SDK 不对外授权、插件只允许在 Avid 认可的宿主(Pro Tools)里运行,JUCE 也没有 AAX 宿主实现——这不是待办项,是没有可行路径(见"ARA 与 AAX")。
- **ARA 目前只到"框架 + 识别"**:ARA SDK 2.2.0 已内置、JUCE 的 ARA 宿主框架已编进程序、声明 ARA 的插件会被标出来;但为音频轨建立 ARA 文档(音频源 / 播放区域)、按 ARA 渲染音频、以及把 ARA 文档存档还都没接上,所以 ARA 插件现在仍然只按普通 VST3 / AU 插入效果器使用(见"ARA 与 AAX")。
- 变速 / 移调使用离线的 WSOLA 时间伸缩 + 线性插值重采样(不是实时算法,极端倍率下瞬态会略糊);PDC 补偿深度上限 32768 样本。
- 插件扫描在独立辅助进程里进行(见"运行"),扫描崩溃、卡死、弹窗都不会影响主程序,扫描本身也不会占住消息线程(窗口在扫描期间照常响应);出问题的插件加入黑名单并在插件列表里标红,右键 `重新启用(并重新扫描)` 可以重试。辅助进程本身启动需要约 0.1 秒,所以一次全量扫描比在进程内扫描略慢一点(已扫描过的插件不会重复扫描)。扫描时唯一不能中途打断的一步是遍历插件文件夹(`停止` 在那一步要等这次遍历结束),单个目录的遍历通常在 1 秒以内。
- 插件仍需在其**自己**的进程里加载后才能使用:如果某个插件在插入到轨道上时自己弹窗或崩溃(而不是扫描时),那是插件本身的问题;扫描结果里能看到原因(`%APPDATA%\SoundX\plugin-scan.log`)。
- **插件自己弹出的窗口(例如 Ozone 的 Preset Manager、Waves 的加载窗口)是插件自己创建的独立窗口**,由插件自己绘制。宿主侧已经保证两件会打断它们的事不再发生:插件面板开着时不做"键盘焦点自愈"(以前 30 Hz 抢焦点会把刚弹出的菜单立刻关掉)、插件编辑器打开后不再自动居中移动(移动宿主窗口同样会关掉插件的弹出菜单)。如果个别插件在自己的菜单里仍然闪烁 / 菜单打不开,可以用 **`SoundX.exe --software-render`** 启动(或设环境变量 `SOUNDX_SOFTWARE_RENDER=1`)把主窗口从 Direct2D 切成软件绘制再试:有些显卡驱动下原生子窗口和 D2D 交换链的合成会互相干扰,软件绘制能绕开这一点。程序还有**崩溃日志**:未处理异常会写到 `%APPDATA%\SoundX\crash-<时间>.log`(异常类型、出错模块 + 偏移、符号化调用栈;编译时保留的 PDB 在旁边时能直接给出函数名和源码行),崩溃报告可以直接把这个文件发回来。
- 延迟补偿(PDC)按“轨道 → 总线/发送 → 母线”的完整路径累加:插件上报的延迟(含插入后才上报、旁通后仍保持对齐)、总线链与母线链都会补偿,导出时会丢掉开头的补延迟样本,所以打印出来的文件和工程时间轴对齐。旁通一个带延迟的插件不会让轨道在时间上跳动。
- 撤销记录是"工程树 + 插件的参数值 / 状态":插件内部**不是参数控制**的东西(采样库、脚本、DSP 内部状态)只在插入 / 移除时整体保存(所以移除后再撤销能原样回来),而在插件窗口里改这些东西只能通过"移除再撤销"找回;另外插件窗口里的输入框(预设名、搜索框)保留自己的 Ctrl+Z。撤销记录最多 200 步。**一次导入算一步撤销**(拖入 / 多选导入一批文件,或者一个多轨 MIDI 文件):一次 `Ctrl+Z` 把这次导入加进来的轨道和片段全部收回,一次 `Ctrl+Shift+Z` 再全部恢复,和 Studio One 一样,不会"每个文件撤一次";单个文件的导入本来就是一步。
- macOS 版:插件扫描的"自动关掉插件弹窗"只在 Windows 上做(macOS 不允许跨线程操作窗口),卡住的插件靠 30 秒空闲超时结束;VST2 宿主在 mac 构建里关闭;录音需要麦克风权限。移植相关的三件事(架构、hardened runtime + entitlements、系统字体)见上面"macOS"一节。
- 目前 Windows 版是 x64;macOS 版用 `package-mac.sh` 构建(默认通用二进制)。
